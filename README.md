# uom

A Java library for typed quantities and units of measurement, implementing JSR-385 (`javax.measure`, unit-api 2.2). It is in development.

Status: milestone 5 done (units core, typed `double` and `BigDecimal` quantities for all 33 quantity types, seven catalogs with prefixes, `quantity.to(system)`, basic unit and quantity formats, the JSR-385 service provider). The systems are `SI` (128 distinct units), `USCustomary` (35), `Imperial` (42), `CGS` (16), `ESU` (22), `EMU` (29) and `Gaussian` (26); `quantity.to(system)` converts to the system's preferred unit for the quantity type. The JSR-385 TCK (`unit-tck` 2.2) passes: 113 of 113 tests; `mvn -q -B clean verify` runs 870 tests. A decimal-preserving quantity parse, locale-aware formats, serialization and run-time loading of `.units` files are not implemented yet. Not released.

## Modules

- `uom-core`: units, dimensions, converters, the `.units` parser, the shared `double` and `BigDecimal` quantity base classes.
- `uom-quantities`: generated typed quantity interfaces, `double` and `BigDecimal` implementations and factories (33 types, 133 generated files).
- `uom-systems`: the generated catalogs (`SI`, `USCustomary`, `Imperial`, `CGS`, `ESU`, `EMU`, `Gaussian`), `UomSystemOfUnits`, unit and quantity formats, the `ServiceProvider`.
- `uom-codegen`: the generator (internal, not published).
- `uom-tck`: runs the JSR-385 TCK against `uom-systems` (test only, not published).
- `uom-examples`: runnable usage examples (not published); see below.

Build and test everything: `mvn -q -B clean verify`.

See [docs/REQUIREMENTS.md](docs/REQUIREMENTS.md) and [docs/DESIGN.md](docs/DESIGN.md).

## Examples

[`Examples.java`](uom-examples/src/main/java/org/tinygears/uom/examples/Examples.java) shows typed quantities and conversion, dividing quantities and `asType`, offset units, `equals` versus `isEquivalentTo`, unit and quantity parsing and formatting, and use through the JSR-385 `ServiceProvider`. `decimals()` shows `BigDecimal` quantities: `0.1 m + 0.2 m` is exactly `0.3 m`, unlike with `double`. `mixedPrecision()`, `contexts()`, `decimalEquality()` and `decimalFormat()` show the precision rule (a `double` operand makes the result a `double`), `MathContext` and `toDecimal`/`toDouble`, `equals` versus `isEquivalentTo` across precisions, and decimal formatting. `systems()` shows `quantity.to(system)`: 1 ft in CGS is `30.48 cm`, 100 °C in US customary is `212.0 °F` (exactly `212 °F` for a `BigDecimal`), the US gallon (3.785411784 L) against the imperial gallon (4.54609 L), and 1 C in Gaussian units. `ExamplesTest` checks the printed output. Run it after a build with:

```
mvn -q -B -pl uom-examples -am install -DskipTests
mvn -q -B -pl uom-examples exec:java -Dexec.mainClass=org.tinygears.uom.examples.Examples
```

## Generated sources

The sources in `uom-quantities/src/main/java/org/tinygears/uom/quantity` and the catalogs in `uom-systems/src/main/java/org/tinygears/uom/systems/` (`SI.java`, `USCustomary.java`, `Imperial.java`, `CGS.java`, `ESU.java`, `EMU.java`, `Gaussian.java`) are generated by `uom-codegen` from `data/quantity-types.txt` and the `.units` files in `data/`, and are committed. After changing `data/`, regenerate from the repository root (the `generate` profile passes `<dataDir> <quantitiesOut> <systemsOut>`):

    mvn -q -B -Pgenerate -pl uom-codegen -am process-classes

`GeneratedSourcesUpToDateTest` fails when `data/` and the committed sources disagree.
