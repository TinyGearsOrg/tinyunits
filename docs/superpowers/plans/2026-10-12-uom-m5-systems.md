# uom Milestone 5: Other Unit Systems and `quantity.to(system)` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Catalogs of typed units for US customary, Imperial, CGS (mechanical) and the three CGS electromagnetic conventions (ESU, EMU, Gaussian), each a `SystemOfUnits` with preferred units, all generated from data files, parsed and formatted by the existing unit format, plus `quantity.to(system)` on every typed quantity.

**Architecture:** One `.units` file per system (`us-customary`, `imperial`, `cgs`, `cgs-esu`, `cgs-emu`, `cgs-gaussian`) next to `si.units`. Three new data directives (`@system`, `@extends`, `@member`) let a system own its definitions, take over the units of another system and list units defined elsewhere; the generator writes one catalog class per file (like `SI`) with layered preferred units that fall back to SI. `to(SystemOfUnits)` is implemented once in the two base classes through a generated `quantityType()` hook.

**Tech Stack:** Java 21, Maven, JUnit 5.10.2, `javax.measure:unit-api:2.2`.

**Spec:** `docs/DESIGN.md` (sections 4 to 7), `docs/REQUIREMENTS.md` (F6, F7, F8, F15 to F19), the follow-ups `docs/superpowers/plans/2026-10-12-uom-m3-follow-ups.md` and `2026-10-12-uom-m4-follow-ups.md`. Branch `m5-systems` is stacked on `ng` (= `m4-decimal` plus the examples); nothing is merged into `main`.

## Global Constraints

- Java baseline 21; Maven multi-module; Apache-2.0; every `.java` file starts with `// SPDX-License-Identifier: Apache-2.0` (generated files: that line plus `// Generated by uom-codegen from data/<files>; do not edit.`).
- Runtime dependencies: only `javax.measure:unit-api` 2.2. No proxies, no reflection in main code; `uom-codegen` must not depend on the generated modules (bootstrap rule).
- Generated sources are committed; regenerate with `mvn -q -B -Pgenerate -pl uom-codegen -am process-classes` from the root; the drift test must pass; output deterministic (LF, stable order).
- Catalog factors are exact (`Factor`, N2): no `double` literals in generated code; every definition is exact except where its source defines it approximately (none in this milestone). Data is authored independently from NIST SP 811 / BIPM / ISO 80000 values, never copied from GNU units (licence risk, REQUIREMENTS section 7).
- Data-file errors carry file and line (F19). Symbols are unique across the files that one parse sees; units that differ between systems use distinct symbols.
- Commit subjects use a conventional prefix (`feat:`, `fix:`, `test:`, `build:`, `docs:`), no emojis; code comments 1-3 lines; tests assert exact values and exception types, not just non-null.
- The three open owner decisions in `docs/TODO.md` (offset-unit arithmetic, `asType` and alternate units, offset-unit products) keep their current behavior.

## Decisions for this milestone

- **D1 Systems (owner-confirmed).** `SI` (exists), `USCustomary`, `Imperial`, `CGS`, `ESU`, `EMU`, `Gaussian`: seven catalog classes in `org.tinygears.uom.systems`, system names equal to the class names. `Imperial` extends `USCustomary`, `ESU`/`EMU`/`Gaussian` extend `CGS`, `Gaussian` also extends `ESU` and lists the EMU magnetic units. F7: the electromagnetic CGS units are conversion factors to SI units of the standard quantity types, not new dimensions.
- **D2 Directives.** `@system Name` (once per catalog file, names the class and the system); `@extends file` (implies `@include`; the units of that file, and transitively of the files it extends, become members of this system, and its `@preferred` lines are inherited); `@member symbol...` (units already defined in an included file become members without a new constant); `@include` alone only makes definitions available for formulas (every file includes `si.units`). `Definitions` gains `system`, `extended` and `members` (records with source and line like `Prefixed`).
- **D3 Membership and constants.** A catalog class has constants for its own definitions only. Its `UNITS` list is its own constants, then the (flattened) `UNITS` of the systems it extends, then the `@member` units referenced through the owning class (`SI.CENTIMETRE`); equal units collapse to the first listed (`UomSystemOfUnits` already does this). `PREFIXABLE` is the own `@prefixed` symbols plus those of extended systems, restricted to members.
- **D4 Preferred units (owner-confirmed).** Every system's `PREFERRED` has all 33 types: its own `@preferred`, else the first extended system's (in `@extends` order), else SI's. `getUnit(Class)` is therefore never null for the 33 standard types. SI keeps today's rule (a factory system unit when no `@preferred`).
- **D5 `quantity.to(system)`.** The typed interface gets `X to(javax.measure.spi.SystemOfUnits)`; the base classes implement `R to(SystemOfUnits)` as `to(system.getUnit(quantityType()))` through a new generated hook `protected abstract Class<Q> quantityType()`. A `null` from a foreign system throws `UnsupportedOperationException("system N has no unit for type T")`; untyped quantities have no standard type and throw the same; a foreign unit returned by the system gives the existing `UnconvertibleException`. Scale and `MathContext` are kept.
- **D6 Untyped units (owner-confirmed).** Poise, stokes and oersted have no standard quantity type: they are `UomUnit<?>` constants (the generator already allows untyped units). Adding non-standard quantity types is a follow-up. The gilbert has the dimension of current and is typed `ElectricCurrent`.
- **D7 Symbol resolution.** Unchanged algorithm (labels, exact symbols across all systems in `UnitSystems.all()` order, then metric prefix on a prefixable unit). Exact symbols win over prefix readings, so `ft` is the foot, not the femtotonne; a regression test lists every string that parsed in SI-only mode and now parses differently (the documented shadow set).
- **D8 Names.** Constant names derive from the unit name as today (`foot` gives `FOOT`); suffix variants: `ft_US`, `mi_US`, `ac_US`, `gal_US`, `ton_US`, `gal_UK`, `ton_UK`, `BTU_IT`, `BTU_th`, `hp_M`.
