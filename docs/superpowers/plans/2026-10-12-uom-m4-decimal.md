# uom Milestone 4: BigDecimal Quantities and the Precision Rule Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every one of the 33 quantity types gets a `BigDecimal` implementation next to its `double` one, with the single documented precision rule (F23: the lower precision wins), a settled decimal `equals` and `isEquivalentTo`, typed factories, and conversions that stay exact where the definitions are exact.

**Architecture:** A hand-written `AbstractDecimalQuantity` (uom-core) mirrors `AbstractDoubleQuantity`; a package-private `Precision` helper classifies operands and converts between `Number` kinds. Each generated `XDecimal` is a thin subclass; the generator also extends the typed interface (`toDouble()`, `toDecimal(MathContext)`, `BigDecimal` factories) and the factory. `AffineConverter`'s exact decimal path is hardened first because every decimal conversion goes through it.

**Tech Stack:** Java 21, Maven, JUnit 5.10.2, `javax.measure:unit-api:2.2`.

**Spec:** `docs/DESIGN.md` (sections 3, 4, 7, 8), `docs/REQUIREMENTS.md` (F5, F20, F23, F24), and the follow-ups `docs/superpowers/plans/2026-10-12-uom-m1-follow-ups.md` (the M4 converter item), `2026-10-12-uom-m2-follow-ups.md` and `2026-10-12-uom-m3-follow-ups.md`. Branch `m4-decimal` is stacked on `ng` (= `m3-catalog` plus the examples module); nothing is merged into `main`.

## Decisions for this milestone

- **D1 Classes.** `AbstractDecimalQuantity<Q extends Quantity<Q>, R extends Q>` in `org.tinygears.uom.core.quantity`, generated `XDecimal` (package-private, final) per type, `UntypedDecimalQuantity` for products, quotients and inverses. Fields: `BigDecimal value`, `UomUnit<Q> unit`, `Quantity.Scale scale`, `MathContext mathContext`. Default `MathContext` is `DECIMAL128` (F23 (4)).
- **D2 Operand kinds (F23 (1), (2)).** `Precision.kind(Number)`: `Byte`, `Short`, `Integer`, `Long`, `BigInteger`, `AtomicInteger`, `AtomicLong` are EXACT (they never lower the precision); `BigDecimal` is DECIMAL; everything else (`Double`, `Float`, other `Number`) is DOUBLE. A foreign `BigDecimal` value has no context and counts as unlimited (highest).
- **D3 Result precision.** DOUBLE beats everything: if either operand is DOUBLE the result is a `double` quantity of the same typed interface, built through the receiver's cross-precision hook. Two decimals give the lower `MathContext` precision (0 = unlimited is highest; equal precision keeps the receiver's rounding mode). EXACT operands adopt the receiver's precision. Scalar `Number` arguments adopt the receiver's precision. Conversion of a `BigDecimal` outside the `double` range throws `ArithmeticException`, never `Infinity` (F23 (3)).
- **D4 Equality (settles the DESIGN open item).** Decimal `equals`: same implementation class, same unit, same `Scale`, `value.compareTo(other) == 0` (so `1.0 m` equals `1.00 m`); the `MathContext` is a computation setting and is not part of equality. `hashCode` uses `value.stripTrailingZeros()`, so equal values hash equal. `LengthDouble` never equals `LengthDecimal`.
- **D5 Equivalence (settles F20 for `BigDecimal`).** After converting `that` into this unit with the calculation context, equivalent when `compareTo == 0` or `|a - b| <= max(|a|, |b|) * 10^(1 - p)`, where `p` is the lowest non-zero precision of the two contexts (34 when both are unlimited). Against a `double` operand the `double` rule applies (relative 1e-12). Different dimensions give `false`; there is no absolute floor, so offset units stay asymmetric near zero as for `double`.
- **D6 Ordering.** `compareTo` converts both to the system unit under the lower context and uses `BigDecimal.compareTo`; against a `double` operand it uses `Double.compare` of the system-unit values. Not consistent with `equals`.
- **D7 Division.** Decimal `divide` rounds to the receiver's context; an unlimited context uses `DECIMAL128` for the division only, so `1 m / 3` never throws. Division by zero throws `ArithmeticException` (decimals have no infinity).
- **D8 Scalar conversion.** A `double` or `Float` scalar becomes the decimal the user wrote (`BigDecimal.valueOf(double)`, `new BigDecimal(Float.toString(f))`); `NaN` or infinity throws `ArithmeticException("not a finite number: ...")`.
- **D9 Bounds.** The scale of a `BigDecimal` value is limited to `|scale| <= 100_000` at construction (`ArithmeticException`), so conversions and `toString` stay bounded.
- **D10 Explicit conversions (F23 (5)).** The typed interface gets `X toDouble()` and `X toDecimal(MathContext mc)`: the same quantity at the other precision, typed. `asType` keeps the receiver's `MathContext` when the factory returns a decimal quantity. `AbstractDoubleQuantity.doubleValue()` (public, unused by any interface) is dropped in favour of these.
- **D11 Factories.** `XFactory.of(BigDecimal, Unit)`, `of(BigDecimal, Unit, Scale)`, `of(BigDecimal, Unit, Scale, MathContext)`, with the same three statics on the typed interface. `QuantityFactory.create(Number, ...)` gives a decimal quantity (DECIMAL128) for `BigDecimal` and `BigInteger` values and a `double` quantity for everything else, as before.
- **D12 Formats.** `UomQuantityFormat.format` prints `BigDecimal.toString()`; `parse` still returns `double` quantities. A decimal-preserving parse is a follow-up (milestone 6). The TCK configuration is unchanged (113 tests).

## Review Focus

1. **Absurd scales.** Converting `1e-20000000` (pure scale and Fahrenheit to Celsius) finishes in well under a second; quantities reject `|scale| > 100000` (Tasks 1, 2, 3).
2. **Mixed precision is symmetric.** For all four combinations `a.add(b)` and `b.add(a)` have the same result type and context; a decimal outside the `double` range never becomes `Infinity` (Tasks 4, 6).
3. **Equality contract.** `1.0 m` and `1.00 m` are equal with equal hash codes, `0` and `0.000` likewise; a different `MathContext` does not matter; `equals` is reflexive, symmetric and transitive across unit changes (Task 3).
4. **Non-terminating and zero division.** `1 m / 3` under an unlimited context, `0 m / 0`, `1 m / 0` (Task 4).
5. **Exact offset units.** `100 degC` in kelvin is exactly `373.15` (not `373.15000000000003`), Fahrenheit to Celsius round trips exactly, degrees to radians under a context rounds once (Tasks 4, 8).
