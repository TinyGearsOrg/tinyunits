# uom Milestone 2: Double Quantities and the Generator Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Typed `double` quantities for a first set of quantity types, produced by an internal code generator from data files, on top of the milestone 1 units core.

**Architecture:** Hand-written base classes in `uom-core` hold all quantity logic. The unpublished `uom-codegen` module reads `data/quantity-types.txt` and `data/base.units` and writes thin generated sources into `uom-quantities` (typed interface, `double` implementation, factory per type, plus a type registry); the generated sources are committed and a test fails when they drift.

**Tech Stack:** Java 21, Maven, JUnit 5.10.2, `javax.measure:unit-api:2.2`; the generator also uses `exec-maven-plugin` 3.2.0 for the `generate` profile.

**Spec:** `docs/DESIGN.md` (sections 4 and 5, milestone 2) and `docs/REQUIREMENTS.md`; milestone 1 follow-ups in `docs/superpowers/plans/2026-10-12-uom-m1-follow-ups.md`. This is the second of six milestone plans; branch `m2-quantities` is stacked on `m1-core` (milestone 1 is not merged yet).

## Global Constraints

- Java baseline 21; Maven multi-module; Apache-2.0; every `.java` file starts with the line `// SPDX-License-Identifier: Apache-2.0` (generated files too, followed by `// Generated by uom-codegen from data/quantity-types.txt; do not edit.`).
- Group id `org.tinygears`; artifacts `uom-*`; package prefix `org.tinygears.uom`; JPMS modules `org.tinygears.uom.core`, `org.tinygears.uom.quantities` (exports `org.tinygears.uom.quantity`).
- Runtime dependencies: only `javax.measure:unit-api` 2.2. `uom-codegen` is not published and is a build-time tool only. No proxies, no runtime reflection in main code (the generator tool may use reflection to check that a quantity type class exists).
- Typed quantities implement the standard interfaces (`javax.measure.quantity.Length`, ...) through own interfaces `org.tinygears.uom.quantity.Length extends javax.measure.quantity.Length`; units stay `Unit<javax.measure.quantity.Length>`.
- Immutable, thread-safe quantities (F12; `Serializable` is milestone 6).
- Arithmetic follows the `Quantity` Javadoc: as if all operands were converted to the system unit first and the result converted back to the unit of the left operand.
- `equals`/`hashCode`: same implementation class, same unit, same scale, same value (`Double.compare` semantics); `isEquivalentTo` has a tolerance; `Comparable<Quantity<Q>>` is implemented and is not consistent with `equals`.
- Generated sources are committed; `GeneratedSourcesUpToDateTest` fails on drift. Generator errors carry file and line (F19).
- Commit subjects use a conventional prefix (`feat:`, `fix:`, `test:`, `build:`, `docs:`), no emojis. Code comments 1-3 lines.

## Decisions for this milestone (confirmed or ruled before planning)

- **D1 Comparable (confirmed by the owner):** quantities implement `Comparable<Quantity<Q>>` (the `Quantity` Javadoc says "all implementations must be Comparable"); this replaces F22.
- **D2 License headers (confirmed):** the one-line SPDX header above on every source file, including the existing ones (Task 1 adds them).
- **D3 Scale:** `Quantity.Scale` is a stored flag (default `ABSOLUTE`); arithmetic never depends on it. `to`, `add`, `subtract`, `negate`, `multiply(Number)`, `divide(Number)` keep the left operand's scale; quantity-by-quantity results and `inverse` are `ABSOLUTE`.
- **D4 Tolerance:** `isEquivalentTo` is true when both values are equal, or `|a - b| <= 1e-12 * max(|a|, |b|)` after converting `that` into this unit; NaN is equivalent to nothing. Constant `AbstractDoubleQuantity.EQUIVALENCE_TOLERANCE`.
- **D5 Offset units:** the Javadoc rule is implemented literally (convert to system units, operate, convert back). Its own example "2 degC + 1 degC = 274.15 degC" does not match that rule (the rule gives 276.15 degC); we follow the rule and the example "2 degC + 2 K equivalent to 275.15 K + 2 K"; record in the TCK follow-up. Linear units take a fast path.
- **D6 No strict overloads:** the design's `Length add(Length)` overloads add no compile-time safety over `add(Quantity<javax Length>)` (generics already reject other types), so typed interfaces only add covariant return types (`R` type parameter on the base class). DESIGN section 4 is corrected in Task 10.
- **D7 Untyped results:** `multiply(Quantity)`, `divide(Quantity)` and `inverse` return `UntypedDoubleQuantity` (phantom type `Untyped`); `asType(Class)` narrows through `ServiceProvider.current().getQuantityFactory(type)`. The real provider arrives in milestone 3; tests here use a test provider backed by the generated `QuantityTypes` registry.
- **D8 Foreign arguments:** a `Quantity` or `Unit` from another implementation whose unit is not a `UomUnit` is rejected with `javax.measure.UnconvertibleException` ("foreign unit implementation").
- **D9 Type set for this milestone:** `Length`, `Mass`, `Time`, `Temperature`, `Area`, `Speed`, `Frequency`, `Radioactivity`, `Energy`, `Dimensionless`; milestone 3 adds the rest of the 34 standard types as data rows.

## Review Focus

1. **Offset units in arithmetic.** `2 degC + 2 K` equals `4 degC`; `2 degC + 1 degC` follows the system-unit rule (276.15 degC); linear units take the fast path; negation, `multiply(Number)` and `divide(Number)` follow the same rule (Tasks 3, 4).
2. **Special doubles.** NaN, infinities and `-0.0` in `equals`, `hashCode`, `compareTo`, `isEquivalentTo`, `toString` and conversion (Task 3).
3. **Foreign arguments.** A quantity of another implementation, a foreign unit, a null argument, and an incompatible unit all fail with a clear exception and never a `ClassCastException` from internals (Tasks 3, 4, 5).
4. **Generator determinism and errors.** Identical output on every run (no timestamps, stable ordering, `\n` line endings); an empty, duplicated, unknown or malformed types file gives a `file:line` error; a scaled or offset system unit and a missing quantity class are rejected (Tasks 6, 7, 8).
5. **Aliasing and state.** Generated classes share no mutable state; the alternate-unit registry (global) gives the same result when the generator and the tests define `Hz`/`Bq` in one JVM (Tasks 7, 8, 9).
