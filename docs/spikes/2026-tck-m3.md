# TCK run, milestone 3

The JSR-385 TCK (`tech.units:unit-tck:2.2`, FULL profile) now runs in the regular build
against uom and passes: 113 run, 113 passed, 0 failed, 0 skipped. The milestone 1 spike
is recorded in `2026-tck-m1.md`.

## Command

```
mvn -q -B clean verify
```

From the repository root (JDK 25, Maven 3.9.16). Results:
`uom-tck/target/surefire-reports/testng-results.xml`. The TCK alone:
`mvn -q -B -pl uom-tck -am test`.

## Setup

- Module `uom-tck` (last in the parent `<modules>`, never published, deploy skipped):
  depends on `uom-systems`, with `unit-tck:2.2` and `testng:7.8.0` at test scope.
  Surefire scans `tech.units:unit-tck` via `dependenciesToScan` and uses the
  `surefire-testng:3.2.5` provider, because the parent's JUnit 5 would otherwise select
  the JUnit Platform provider and find 0 tests.
- `UomTckConfiguration` (registered in `META-INF/services`): unit class `UomUnit`,
  dimension class `UomDimension`, the 33 quantity implementation classes (from
  `QuantityTypes.factory(type).create(1, systemUnit).getClass()`), converters identity,
  scale 1000, shift 273, test units the 7 SI base units, `ONE`, `SI.KILOMETRE`,
  `SI.DEGREE_CELSIUS`, `SI.NEWTON`, m/s, the 7 base dimensions, formats `UomUnitFormat`
  and `UomQuantityFormat`, and `getUnit4Type` backed by `SI.SYSTEM`.
- The SPI tests use the real `UomServiceProvider` from `uom-systems`; no stub, no Indriya.

## What changed since the spike

- Spike: 113 run, 85 passed, 28 failed. Now: 113 passed. Same count, same profile.
- The 28 spike failures were all missing features, now provided: quantity classes (2),
  default unit and quantity formats (2), and the provider services (24:
  `SystemOfUnitsService`, `FormatService`, a `QuantityFactory` for all 33 API types).
- The stub provider is gone; the TCK finds `UomServiceProvider` through
  `META-INF/services`.
- The test units now come from `SI` (named units with symbols) instead of `BaseUnits`.
- No defect surfaced, so no module was changed for the TCK.

## What a pass means

The TCK mostly checks method existence: the unit, dimension, converter, prefix, quantity
and format tests only verify, by reflection, that a public method with a given signature
exists, and never call it. The substantive checks are few: the base units' dimensions,
the factory `Scale` round trip, prefix counts, and that every symbol of every unit in
every available system of units round-trips through the default `UnitFormat` and
`QuantityFormat` (`parse(u.toString())` equals `u`; `parse("1 " + u)` has unit `u` and
value 1). Passing is necessary for N1 but is not evidence of correctness; the behaviour
the Javadoc specifies is covered by the modules' own tests.
